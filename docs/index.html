Volta AI Development Lifecycle

Eight agent skills that take a piece of customer work from an agreed problem to a verified change in production. Version 1.1.0.

Each skill hands its result to the next, so use them in order: problem brief, solution brief, scope, document, orchestrate (which runs start-work for you), then ship it. Grill me is a helper you can bring in at any stage to stress-test a plan.

Download all eight or browse the source on GitHub.

Quick start for builders

If Volta has asked you to build part of a customer project:

  1. Install the skills (below) and open your agent tool in the project's repository.
  2. Fill in the solution brief. Run /solution-brief in Guide mode on the brief Volta sends you, and send back the file it saves.
  3. Wait for the 1.0 brief. Volta reviews it and sends you the approved copy. Each of its increments becomes one piece of work.
  4. Write the product contract. Run /scope on one increment. It writes what must be true when you're done onto a GitHub issue.
  5. Write the delivery contract. Run /document on that issue. It adds how you'll build it and how each requirement will be proved.
  6. Build it. Run /orchestrate. It runs builder agents, checks their proof and comes back to you only for decisions.
  7. Ship it. Run /ship-it. It commits, opens and merges the pull request, and confirms the change works in production.

To see what a finished issue looks like after steps 4 and 5, read the worked example.

Good to know

/ship-it merges the pull request itself once its checks pass. If the repository has no required reviews and you don't administer it, it tells you and asks before merging. Agree with the customer how changes get reviewed before you use it on their repository.

Install

Download the full set and unzip it into your agent tool's skills folder, keeping the skill folders side by side. Several skills use files that ship with another one, so install all eight.

Staying up to date

On GitHub, choose Watch → Custom → Releases to hear about new versions. The simplest way to stay current is to clone the repository once, link its skill folders into your tool's skills folder, and run git pull to update. The README has the two commands.

What you need

  • Claude Code, Codex or another agent tool that loads skills from a folder and can run sub-agents. Grill me works anywhere, including the Claude app.
  • git, and the project in a GitHub repository, with the GitHub command line tool (gh) signed in to an account that can read and write its issues and pull requests.
  • Python 3 for the contract script. Nothing else to install.
  • The project's own test and build commands, written down in the repository so agents can find them.
  • Any credentials the project needs, provided the way the project documents. The skills never ask you to paste a secret into the chat.

Without Volta's systems

Some steps use Volta's internal tools, such as its operating database, project context maps and task hub. Each of those steps says so and is skipped when the tool isn't there. Problem brief, and the set-up and review parts of solution brief, are run by Volta.
